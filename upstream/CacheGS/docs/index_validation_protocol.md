# Independent index validation protocol

This protocol implements the accepted [index plan](../../docs/gdmgs_index_implementation_plan.md), [ADR 0008](../../docs/adr/0008-gdmgs-mesh-and-index-experiment-scope.md), and its production ORI update in [ADR 0009](../../docs/adr/0009-pixel-depth-ori-for-index-performance.md). Production now uses discrete native-pixel mesh depth and maximum-depth tiles. The user's scene, image-quality, and timing scope remain unchanged.

## Complete setting and evidence origin

The required scenes and evaluation counts are amsterdam 161, barcelona 160, bilbao 129, chicago 160, hollywood 125, pompidou 161, quebec 160, rome 158, drjohnson 263, playroom 225, train 301, and truck 251: **12 scenes and 2,254 frames**. `small_city` / MatrixCity is the sole user exclusion. Native resolution means each checkpoint's original camera loader and resolution settings; source JPEG dimensions may differ from the configured renderer dimensions, such as 1920 × 1080 source images rendered at 1600 × 900 by the original configuration. No new downscaling is allowed.

The existing A/B survey is historical evidence. Current full geometry exports and actual experiment runs enumerate camera inputs as part of their authorized work; those generated manifests must be compared with the A/B inventory, retaining pose, image name, split, original UID, resolution scale, FoV, and image dimensions. The independent verifier has **not** claimed a separate current filesystem rescan: an additional remote inventory command was denied before execution. No retry or alternate path was used for that denied action. New main-work manifests establish current execution evidence, and checkpoint paths, iteration, size and modification time establish the requested source inventory without content digests.

## Current discrete production oracles

`tests/gdmgs/test_pixel_depth_oracles.py` independently computes camera rays at `(column + 0.5, row + 0.5)` using calibrated angular bounds and inverse W2C, then applies double-precision Möller–Trumbore intersections to complete mesh triangles. Directions remain unnormalized so ray distance is camera-z. This is the reference for **discrete pixel centers**, not continuous angular coverage. It imports no production projection, interpolation, ray intersection or pooling helper.

GPU cases compare complete diagnostic pixel depth and coverage against those rays, including an asymmetric off-center image domain, camera rotation/translation, a foreground patch that exposes a vertical flip, nearest overlapping depth layers, perspective-correct slanted depth, near/far rejection, a near-plane-crossing triangle, an uncovered pixel, padded right/bottom pixels and empty geometry. A separate literal tile maximum establishes that any unknown or padded pixel makes its tile Unknown, and that every finite tile bounds every covered pixel it contains. The between-pixel microhole fixture intentionally permits a finite tile when no pixel-center ray intersects the hole; the result explicitly carries `continuous_coverage_certificate: false`.

GPU tests require an explicit leased run with `GDMGS_TEST_PIXEL_GPU=1`; skipped CUDA cases in an ordinary CPU invocation are not counted as production validation. Both R1 and R2 must use the same native rasterization, clipping, sidedness, pixel centers, tile layout and rounding policy. Their actual ORI transfers, GPU raster/interpolation/reduction and required CPU download remain inside `timings_ms.ori` and its enclosing query/total measurements. Static mesh upload and raster context creation remain recorded offline initialization.

## Retained independent geometry and exact-reference tests

`tests/gdmgs/test_index_oracles.py` imports the public native query APIs as the system under test. Its oracles do not import production clipping, coverage, support, or range helpers.

- Triangle relevance uses a separate NumPy Sutherland–Hodgman polygon clip against all camera-frustum halfspaces. Every truly intersecting triangle must occur in native scan and BVH results; those two native result sets must also agree exactly. Native retrieval intentionally admits conservative corner false positives, so exact geometric intersection is a required subset, not an incorrectly imposed equality. Fixtures include long triangles whose centroids are outside, camera-inside-root, near-plane crossings, transforms, finite far planes, empty geometry, and whole descendant bounds.
- Continuous coverage uses analytically constructed surfaces: a square split by a shared diagonal requires the union of two triangles; a partial strip covers exactly half the cells; four rectangles leave an interior open hole only `2e-7` angular units wide; near-plane clipping exposes the unoccluded half of a slanted plane. An exact union fixture establishes coverage from the polygon definitions. Sample rays are not accepted as a continuous-coverage proof.
- Occluder depth tests a slanted plane with independently known maximum camera-z. The bound must lie at or above that maximum. The test does not compare an ORI cell against its own production depth formula.
- Anchor fixtures place separate PLY rows at duplicate coordinates, include a second decoder offset in front of a wall, cross the near plane, and include an entirely offscreen support. A known complete wall must remove both wholly occluded duplicate rows and retain the crossing supports. All selected IDs preserve input FoV order. DFS/rank inversion and expanded half-open ranges must exactly denote selected source rows. Unknown ORI cells keep the affected anchor. All possible covariance rotations are bounded through independently computed sphere coordinate extrema.

The exact continuous-coverage fixtures remain tests of the historical reference implementation. They do not prove the new discrete production path and their subpixel-hole guarantee is not imposed on it. Anchor identity/support and triangle retrieval fixtures remain applicable. Those fixtures complement review of gsplat's actual cutoff, projection, rounding and screen-space covariance expansion. Frozen-checkpoint image-quality acceptance is a distinct empirical gate. An index over a geometrically inaccurate mesh can still fail image quality.

## Frozen raw-output schema

The standalone auditor is `tools/gdmgs/audit_index_results.py`:

```text
python tools/gdmgs/audit_index_results.py --run-root RUN_DIRECTORY --output AUDIT_DIRECTORY
```

It reads `manifest.json`, `records.jsonl`, each scene's saved `dfs_to_row` NumPy array, terminal `scenes/SCENE/status.json`, and `quality/SCENE/000000.npz` through the scene's final frame. It streams one image bundle at a time and writes `independent_per_frame.jsonl` plus `independent_summary.json`. Terminal status must be complete, preserve source checkpoint metadata, and report all expected frames. A missing file, duplicate row, mismatched camera, changed quality contract, nonfinite pixel, invalid ID, incomplete trajectory, or unmeasured required timing fails closed. Final manifest scope is `full_setting`; each contributing scene is `full_scene`. Explicit development runs cannot be relabeled into final acceptance even if they happen to list every frame.

The manifest contains schema version 1; explicit run, camera, scene, mesh, index and settings identities; exactly the 12 scenes; their full ordered frames; checkpoint paths/iteration/file metadata; `required_modes: [R0,R1,R2]`; three formal timing repetitions with rotated mode order; recorded machine/device identity; positive CPU and Torch thread budgets; and explicit `false` settings for cache, precompute and scheduling. Each scene records `ori_backend: pixel_depth`, `ori_definition: native_pixel_depth_tiles_v1`, a positive frozen `tile_size`, and `ori_image_size_source: frame.render_dimensions`. Actual R1/R2 ORI counters must agree with those values, report the exact original and padded width/height for that frame, explicitly reject a continuous-coverage claim, and account for required upload/download buffers. Historical exact-reference diagnostics cannot pass this production definition check. Identities are ordinary labels and hardware identifiers, not computed content digests.

Each raw quality NPZ contains float32 CHW `gt`, `r0`, `r0_repeat`, `r1`, and `r2` at the manifest's exact renderer dimensions. Scalar `run_id`, `scene`, `frame_index`, `camera_token` and `mesh_token` must match the manifest. Integer evidence uses int64: original `fov_ids`; each indexed mode's actual `r1_fov_ids` / `r2_fov_ids`, `r1_selected_ids` / `r2_selected_ids`, and actual consumer `r1_decoded_anchor_ids` / `r2_decoded_anchor_ids`; sorted unique `scan_triangle_ids` and `bvh_triangle_ids`; and each indexed mode's `raw_ranges` and `formal_ranges`. Actual FoV IDs must equal the original frame's IDs, and actual decoder requests must equal the query selection in order. Per-scene DFS permutation is saved and validated once. If range reuse is implemented, `r3_selected_ids` and its raw/formal range denotations must equal R2's rebuilt selection; no Gaussian cache is introduced by this index-state test.

Every formal timing row identifies run, scene, frame, mode, repetition, camera and settings; its completion status is `complete`. Recorded FoV, selected, culled and triangle counts must be valid integers and agree with that frame's actual quality-array counts on every repetition. Measured milliseconds are stored under `timings_ms` with fields `fov`, `d2h`, `retrieval`, `ori`, `anchor`, `h2d`, `decode_raster`, `query`, and `total`. R1 and R2 measure all these scopes; their enclosing query includes FoV, transfers, retrieval, ORI, anchor traversal, range materialization and final-ID transfer. Their query must equal the sum of those six stages, and total must equal query plus decode/raster, allowing only `1e-6` ms absolute or `1e-9` relative floating-point accumulation error. R0 executes the original fresh renderer and requires a real enclosing `total`; an uninstrumented R0 component is null, never a fabricated zero. Quality capture, array copying for audit, image saving and metric computation occur outside formal timed frame work. Required transfers inside the query remain timed.

## Image quality and nonfinite rules

The user's gate is applied to **every** frame, including R1 and R2, against the same frame's R0 and GT: PSNR drop must be at most **0.1 dB** and SSIM drop at most **0.002**. R0's repeated fresh capture also records baseline noise; if the repeated baseline itself fails these limits, the run fails its baseline stability check. The final audit and runner both retain those repeated-baseline failure frames. No scene mean or aggregate can hide a failed frame.

Existing `metrics.py` reads saved PNG images. To retain its preprocessing without writing extra PNG files, the independent auditor reproduces torchvision's float32 conversion: multiply by 255, add 0.5, clamp to [0,255], cast to uint8, and divide by 255. It independently evaluates PSNR from the RGB mean squared error and SSIM with an 11 × 11 Gaussian window, sigma 1.5, zero padding, constants 0.01² and 0.03², and a mean over RGB/spatial positions. Separable float64 convolution evaluates the same definition independently of the production Torch helper; a direct 2D-convolution test verifies equivalence. The accepted thresholds are strict as written, with no post-hoc tolerance widening.

Exact zero MSE gives positive-infinite PSNR. Positive-infinite baseline and candidate give zero drop; an exact baseline followed by finite candidate PSNR gives infinite degradation and fails. A finite baseline followed by exact candidate PSNR improves the score. Nonfinite input pixels fail before metric evaluation. JSON encodes infinities as explicit strings rather than invalid JSON numeric tokens.

Direct raw-RGB comparisons use the original float32 outputs promoted to float64 for subtraction; they are **not** clipped or quantized. Report exact equality, maximum absolute error, mean absolute error, MSE and direct PSNR. These detect changes that disappear after PNG rounding. Keep the worst PSNR and SSIM frame identities and maximum raw pixel difference per scene.

## Timing summaries and separate completion gates

Each frame and repetition remains in the timing file. Report per-scene component p50, p95, maximum and full sums. The primary ratios divide sums over identical complete frame/repetition sets:

1. `sum(R1 query) / sum(R2 query)` for the complete query.
2. `sum(R1 total) / sum(R2 total)` for scan-versus-index fresh rendering.
3. `sum(R0 total) / sum(R2 total)` for actual end-to-end improvement over the original fresh path.
4. `sum(R1 retrieval) / sum(R2 retrieval)` as a supplementary mesh retrieval component.

Values below one are slowdowns. The combined number is a ratio of elapsed sums across all scenes, never the arithmetic mean of per-frame speedups or FPS. Offline depth extraction, mesh construction/cleanup, index build/load, artifact disk size and memory remain separate. Amortization must use the measured offline cost and the positive per-frame saving; no break-even exists when online time does not improve.

A passing raw-output audit proves only the measured full-output contract. Overall completion additionally requires current complete main-work manifests, independent geometry tests, justified mesh adoption, actual decoder selection instrumentation, supported compatibility/training regressions after shared changes, effective known-wall removal and observed real traversal/culling counters, nonauthor review resolution, and final scoped cleanup. The auditor does not convert missing evidence in those separate gates into a completion claim.
